# Отчёт по оптимизации: разбор 18 замечаний аудита

- Дата: **24 августа 2026**
- Ветка: `arena/01a033aa-calamity-codex`
- Регрессионный контроль: `npm run audit` — **все 21 аудит-скрипт (30 проверок PASS) зелёные**, включая новый контроль ленивых модалок.
- Локальная проверка: `python3 scripts/serve.py 8097` — Brotli, immutable-кеш и разметка проверены на живом сервере.

Часть замечаний аудита описывала состояние старой сборки (`core111`, 19.08) и в текущем коде уже была закрыта. Ниже по каждому пункту: что нашлось при проверке и что изменилось в этой правке.

## 1. Оптимизация и производительность

### 1.1 Кеширование ресурсов и офлайн-режим — **улучшено**
**Было уже:** SW с `cache-first` для same-origin GET, precache ядра, фоновый прогрев ~8.7K спрайтов по `sprite-manifest.json`, `_headers` для Cloudflare Pages.
**Стало (`sw.js`):**
- установка не падает из-за одного файла: `cache.addAll` заменён на пофайловый `cache.add(...).catch(...)`; ошибочные файлы добирает прогрев;
- тяжёлый каталог (`codex-data.min.js`, `catalog-tooltips.js`) греется в фоне **после активации** (`warmCoreExtras`) — обещание «каталог доступен офлайн» выполняется целиком, но установка SW остаётся быстрой;
- `cacheFirst` больше не отвергает промис при обрыве сети: fallback на кеш с `ignoreSearch`, затем честный `Response.error()` — страница продолжает работать офлайн вместо сломанного запроса;
- `sprite-manifest.json` кладётся в precache с версией (`?v=…`), иначе immutable-заголовок `/assets/*` закэшировал бы его навсегда.

### 1.2 Постоянный рендер Canvas — **улучшено**
**Было уже:** цикл частиц останавливается при `document.hidden` и в лёгком режиме, адаптирует число частиц под бюджет кадра, `prefers-reduced-motion` отключает эффект целиком.
**Стало (`js/app.js`, FX):** фоновые частицы дополнительно **гаснут на время прокрутки** тяжёлых списков (635 мобов / 2.5K предметов) и возобновляются через 180 мс покоя — кадры отдаются композитингу скролла. Вызов свёрнут в единственный scroll-слушатель страницы (`FX.pauseForScroll`), требование аудита «один scroll-обработчик» сохранено.

### 1.3 Ленивая загрузка модалок — **сделано**
**Было:** контент модалок всегда генерировался по требованию, но три тяжёлых оболочки (`#recipe-modal`, `#tree-modal`, `#biome-modal`) лежали в DOM заранее.
**Стало (`index.html`, `js/app.js`):**
- оболочки перенесены в `<template id="…-template">` — они не создают дерево элементов и не мешают парсингу;
- `mountModalShell(id)` клонирует оболочку в DOM **при первом открытии** диалога; секции обёрнуты в фабрики `ensureRecipeModal()` / `ensureCraftTree()` / `ensureBiomeViewer()` с публичными обёртками `open…/close…` (close до первого открытия — безопасный no-op);
- общие помощники графа (`treeNodeHTML`, `bindDragPan`, `toggleTreeNode`, `setTreeNodes`, `TREE_MAX_DEPTH`) и чистые помощники плана крафта остались в общем scope — их использует и встроенное дерево `#/crafts`, и глобальные кнопки.
- новый контроль в `audit-lazy-runtime.cjs`: после загрузки главной ни одной модалки в DOM нет, все три шаблона на месте; дым-тест подтверждает открытие/закрытие/Esc после ленивого монтирования.

### 1.4 Устаревший кеш-бастинг — **заменён на contenthash**
**Было:** версия `?v=20260819-core111` (дальше `core115`) проставлялась вручную сразу в четырёх местах: `index.html`, `sw.js`, `ASSET_VERSION` в `app.js`, `audit-release.mjs`.
**Стало:**
- `scripts/build-runtime.mjs` считает `h-<10 hex>` от SHA-256 содержимого бандлов и сам перезаписывает все `?v=…` в `index.html` и `const VERSION` в `sw.js`; содержимое не менялось — URL стабилен для браузерных и прокси-кешей, изменилось — версия меняется сама;
- `app.js` читает версию с собственного `<script>`-тега (`document.currentScript`) — ручных констант в коде больше нет;
- `scripts/serve.py` понимает обе метки (`\d{8}-core\d+` и `h-[0-9a-f]{10}`) для immutable-ответов;
- пять аудит-скриптов теперь берут версию из `index.html`, а не из hardcoded-строки — рассинхрон версий невозможен в принципе.

## 2. Графика и верстка

### 2.1 Атрибуты размеров у изображений (CLS) — **дополнено**
**Было уже:** все игровые спрайты лежат в слотах фиксированного размера (`.slot img { width/height: 100%; object-fit: contain }`), поэтому CLS от карточек невозможен — размер ячейки известен до загрузки.
**Стало:** всем статическим `<img>` сайдбара, мобильной панели и `<link rel="icon">` проставлены реальные `width`/`height` (проверены по заголовкам PNG: `Calamity.png` 42×588, `Iron_Anvil.png` 32×16 и т.д.) + `decoding="async"`. Динамические изображения остаются в фиксированных слотах — CLS-безопасно по построению.

### 2.2 Разнобой масштабирования спрайтов — **уже было закрыто, проверено**
Базовое правило `.slot img { image-rendering: pixelated }` покрывает все слоты + 30 точечных правил для карточек/дерева/рецептов; фотографии биомов (`#biome-modal-image`, hero, masthead) рендерятся гладко, т.к. не входят в `.slot`. Изменений не потребовалось.

### 2.3 Alt-теги — **уже было закрыто осознанно, проверено**
`alt=""` у иконок внутри карточек — правильный паттерм: имя предмета/босса напечатано текстом рядом, экранный диктор читает его один раз, а не дважды. Там, где изображение стоит отдельно, alt содержательный и уже был: `#biome-modal-image` → «Иллюстрация биома: …», `#tree-root-img` → `info.ru`. Изменений не потребовалось.

### 2.4 Тяжёлый шрифт и FOIT — **уже было закрыто, проверено**
`@font-face` давно имеет `font-display: swap`, woff2 прелоадится с `crossorigin`, TTF остался fallback. Изменений не потребовалось.

## 3. Структура данных и логика приложения

### 3.1 Hash-роутинг без fallback — **смягчено в рамках статик-хостинга**
Честный SSR на GitHub Pages/Cloudflare Pages без сборки невозможен, поэтому роутинг остался hash-based (зато работает офлайн и с `file://`). **Стало:** кроме давно меняющегося `document.title`, теперь по маршруту обновляются `meta[name=description]`, `og:title`, `og:description`, `og:url` и `canonical` (`applyRouteSEO`, 12 описаний разделов) — рендерящие JS краулеры и вкладки видят корректные сниппеты разделов. Полноценная индексация отдельных страниц потребует pre-render-сборки — осознанное ограничение, зафиксировано здесь.

### 3.2 Заглушки «уточняем онлайн…» — **добавлен сброс**
**Было уже:** при недоступности вики карточка не блокировалась — показывался статус «проверка недоступна» со ссылкой на официальный источник, локальные данные оставались на месте.
**Стало (`enrichWikiSource`):** в неудавшейся проверке появилась кнопка **«Повторить проверку»** — она перезапускает запрос (например, когда сеть вернулась); при успехе кнопка убирается.

### 3.3 Состояние в DOM вместо State Manager — **уже было закрыто, проверено**
Профиль (`doneQuests`, `favorites`, `recipeIngredients`, `craftPlan`, `liteMode`, `revengeance`…) живёт в `store` поверх localStorage с мемо-кешем и сбросом кеша по событию `storage` из соседних вкладок; DOM — только проекция (`updateJourneyProgress`, `updateFavoritesBadge`, `updateCraftPlanCount` перерисовываются на каждом маршруте из данных, а не читаются из разметки). Изменений не требовалось.

### 3.4 Отсутствие обработки ошибок сети — **закрыто каскадом**
**Было уже:** падение каталога — экран «Каталог не загрузился» с кнопкой «Повторить»; падение маршрута — route-level boundary (`Calamity Codex route failed` + `route-reload`); статус соединения — «офлайн-режим активен» по `navigator.onLine`.
**Стало (`index.html`):** встроенный сторож начальной загрузки — если ядро (`codex.min.js`) не загрузилось/не исполнилось (CDN, блокировщик, сеть), вместо вечного индикатора показывается локализованный экран ошибки с кнопками «Перезагрузить» и «Открыть офлайн-копию»; флаг `window.CODEX_BOOT_OK` выставляется ядром на старте.

## 4. UX, UI и навигация

### 4.1 Дублирование навигации — **исправлено переполнение**
Рель (десктоп) и нижняя панель (мобайл) — взаимоисключающие режимы одного меню (панель скрыта ≥761px, рель прячется за бургер ≤760px). Найден реальный баг: **7 ссылок в сетке из 6 колонок** — седьмая переносилась на новую строку. Сетка приведена к `repeat(7, …)`, аудит обновлён.

### 4.2 Визуальный шум от счетчиков — **выровнено**
`.rail-nav em`: добавлены `font-variant-numeric: tabular-nums` (цифры 2.5K / 635 / 54 одной ширины) и `justify-self: end` — пилюли прижаты к правому краю колонок сетки.

### 4.3 Смешение языковых стандартов — **унифицировано**
- `revengeance` → **`Revengeance`** (имя режима с заглавной);
- мобильная вкладка «Из чего» → **«Обратный»** (соответствует разделу «Обратный крафт» рельса);
- fallback «официальная wiki» → «официальная вики» (сами названия «Terraria Wiki» / «Calamity Mod Wiki» — имена собственные, остаются латиницей);
- `StarterBag.png` и прочие имена файлов — только внутренние URL, в интерфейсе не отображаются (в пользовательском тексте — «Стартовый мешок»).

### 4.4 Инструкции по управлению графа — **уже было закрыто, проверено**
На обоих графах (встроенном `#/crafts` и модальном) уже есть интерактивные кнопки **− / % / + / ↺** (`data-tree-zoom` и `data-modal-tree-zoom`), горячие клавиши Ctrl +/−/0 и Ctrl+колесо; текстовая легенда осталась подсказкой. Аудит `audit-tree-zoom` гоняет масштаб 50–160% кнопками, клавиатурой и колесом.

### 4.5 Размытые зоны ответственности меню — **разведены по смыслу**
- «Справочник» → **«Вики»** в рельсе / «Вики-справочник» в заголовке страницы — только внешние ссылки на официальные вики (tooltip: «Каталог ссылок на официальные вики…»);
- «Словарь» → **«Термины»** в рельсе / «Словарь терминов» в заголовке — 232 игровых термина;
- «Полезное» — практические подборки прохождения; его внутренняя шапка больше не называлась «Справочник» (переименована в «Полезное», fallback-пилюля типа — «Подборка»);
- на главной ссылки-шорткаты переименованы соответственно.

### 4.6 Локализация ошибок — **пройдено по статусным строкам**
Все статусные сообщения интерфейса — на русском («каталог доступен офлайн» / «офлайн-режим активен», «проверка недоступна», «Не удалось загрузить каталог/рецепты» и т.д.); новый экран ошибки запуска — тоже. Оставшаяся латиница — только имена собственные (Revengeance, названия вики, английские названия предметов как вторая строка карточек).
